# v3.0.0-preview.9 release notes

[中文](v3.0.0-preview.9.zh-CN.md) | **English** · [Download this release](https://github.com/jyongli/codex-quota-strip/releases/tag/v3.0.0-preview.9)

## Direct local Token display

- API-key/external-provider mode shows `Tok` and a compact count in the tray; the strip and Settings show `Run used 1.3K Token | Left —`. Hover and Settings details retain exact integers.
- Counts completed/interrupted requests successfully recorded during this app run, not the account bill. Restart/authentication/recording-toggle/history-directory changes reset the meter; language/interval changes do not. Existing CSV history stays intact.
- Reuses existing file notifications and persisted deduplication, adds only real total tokens and does not double-count cached/reasoning subsets. Replay and manual refresh do not inflate totals. Disabled/failed recording shows `—`; missing/partial data or the 4096-entry limit shows a lower-bound `+`. CSV logging continues.
- Remaining balance stays `—` because the ordinary API-key flow does not expose it here. No Admin Key, additional network queries, polling or resident service is added.
- ChatGPT subscriptions retain actual quota percentages; request lists/charts remain available.

## Choose a download

| System / purpose | File |
| --- | --- |
| Windows 10 1809+ / 11, Intel or AMD x64 | `CodexQuotaStrip-windows-x64-setup.exe`, per-user installation wizard. |
| Windows x64 portable | `CodexQuotaStrip-windows-x64.zip`; Windows 11 ARM64 emulation has not been tested on hardware. |
| Ubuntu 22.04/24.04 or Debian 12, amd64 | `CodexQuotaStrip-linux-x86_64.deb`, install with apt. |
| Fedora 43, x86_64 | `CodexQuotaStrip-linux-x86_64.rpm`, install with dnf. |
| Other glibc Linux x86_64 / no sudo | `CodexQuotaStrip-linux-x86_64.tar.gz`, extract and run `bash install.sh`; system libraries are required. |
| macOS 14+, Apple Silicon or Intel | Universal `.dmg` recommended; `.pkg` and `.zip` are also available. |

Quit the old app before installing/updating portable files. Reuse the installation directory to preserve settings and logs. Linux window following requires X11; Wayland uses tray mode. macOS is ad-hoc signed and has no Developer ID signature/notarization; window following needs Accessibility access.

`SHA256SUMS.txt` verifies attachments; `BUILD-INFO.txt` records build/source identity. The two Source code downloads contain source files.
